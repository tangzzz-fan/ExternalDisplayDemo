## xcodebuild 构建 / 运行验证

结论：可用 xcodebuild 正常构建并运行。

环境：
- Xcode 27.0 (27A266a)，XcodeGen 2.46.0
- 本机仅安装 iOS 27.0 模拟器运行时（24A434）
- 已启动设备：iPhone 18 Pro

构建命令（derivedData 输出到 `.scratch/DerivedData`，不污染系统）：

```sh
xcodebuild -project ExternalDisplayDemo.xcodeproj \
  -scheme ExternalDisplayDemo -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' \
  -derivedDataPath .scratch/DerivedData build
```

xcrun simctl launch booted com.jove.externaldisplaydemo -mockExternalDisplay   # 带模拟外接屏
xcrun simctl io booted screenshot .scratch/shots/launch.png

验证结果：

## 补充三：解释「模拟器里外接屏内容为何能直接渲染」

用户提问：模拟器屏幕上能看到外接屏内容，机制是什么。

答案：**不是模拟器支持外接屏**，而是 `Sources/Debug/MockExternalDisplay.swift`
在**手机屏自己的 `UIWindowScene`** 上叠了第二个 `UIWindow`，全程不碰任何外接屏 API。

链路：`MainSceneDelegate.scene(_:willConnectTo:)` 建好主窗口后调
`MockExternalDisplay.shared.bootstrap(on: windowScene)` → `isEnabled` 读启动参数
`-mockExternalDisplay` → `install()`：

- windowScene 用的是**手机屏那个**，不是外接屏
- 尺寸 = `windowScene.coordinateSpace.bounds` 内缩 (20, 60) 后按 aspect 居中 letterbox
- `windowLevel = .normal + 1` 盖在主窗口之上，`isHidden = false` 显示
- rootViewController 挂 `UIHostingController(rootView: ExternalDisplayRootView(...))`
  —— 与真机 `ExternalDisplaySceneDelegate` 挂的是**同一个视图类型**
- `PassthroughWindow.hitTest` 恒返回 nil → 触摸落到下层窗口，表单照常可点
- `ExternalDisplayMonitor.attachMock(...)` 以 `source == .mock` 登记，手机端显示橙色「模拟」徽章

**分辨率是伪造的**：`scale` 硬编码 3，`Int(rect.width * scale)` 由 letterbox 尺寸推出，
并非真实屏幕参数。真机路径才读 `windowScene.screen.nativeBounds` / `.nativeScale`。

> 发现的文档不一致（未改动，待用户决定）：README 第四节与 `PhoneRootView.debugSection`
> 都写「收起它即可正常操作表单」，但因 `PassthroughWindow` 已做触摸穿透，
> 不收起也能操作表单 —— 只是视觉上被那块 16:9 黑框盖住。该表述容易让人误以为会挡交互。

## 补充四：外接屏滚动能力 + 手机端遥控板（已实现）

### 结论：外接屏不支持任何滚动/手势

两个独立原因，任一即足以失效：
1. role `windowExternalDisplayNonInteractive` 非交互，`window.isUserInteractionEnabled = false`；
2. mock 路径 `PassthroughWindow.hitTest` 恒返回 `nil`，触摸全穿透。

所以在外接屏视图树里加 `ScrollView` / `.gesture` 无效 —— 手势到不了那棵树。
外接屏是纯输出设备，输入必须从手机侧中继。

### 新增文件

- `Sources/Core/RemoteControl.swift` — `@MainActor @Observable` 单例，
  持 `scroll`(0...1 归一化) / `zoom`(1...3) / `pointer`(归一化 CGPoint?) /
  `tapCount` / `lastEvent`，方法 `scroll(by:)` `scroll(to:)` `setZoom` `zoom(by:)`
  `movePointer(to:)` `tap()` `scrollToTop()` `reset()`。
- `Sources/App/RemoteControlPad.swift` — 手机端遥控板：`DragGesture(minimumDistance: 0)`
  拖动滚动 + 采集落点、`MagnifyGesture` 捏合缩放、缩放 Slider、状态读数、
  回到顶部/轻点/复位按钮。右侧有滚动位置指示条。

### 改造

- `Sources/ExternalDisplay/ExternalDisplayRootView.swift` — 重写为：可滚动内容列
  （标题 + 14 条内容条目）、画布 `.scaleEffect(zoom)`、橙色光标环、轻点涟漪、
  右下角固定 HUD（时钟 + 滚动/缩放读数）。新增私有 `ScrollMetrics` 结构
  按视口尺寸换算归一化进度 → 实际位移。
- `Sources/App/PhoneRootView.swift` — Form 插入 `remoteSection`（「遥控外接屏」）；
  顺带修正 debugSection 里「收起后即可正常操作表单」的过时表述。
- `README.md` — 新增第四节「交互：外接屏收不到触摸，怎么办」，原四/五/六顺延为五/六/七；
  踩坑清单加第 9、10 条；迁到真实项目加一条。

### 关键坑（已写进 README 第 10 条）

`.frame(width:height:)` 不指定 alignment 时**默认居中**。滚动内容高约 446pt、视口约 203pt，
居中会把内容上移 121pt，表现为「滚动起点凭空少了两条内容」。必须
`.frame(..., alignment: .topLeading)` + `.clipped()`。第一版截图即踩到（起点显示条目 03 而非 01）。

## 补充五：遥控板改底部常驻遥控台（同日续，消除遗留风险）

上一轮把「触控板在 Form 内、`DragGesture` 与外层竖向 pan 手势竞争」列为待手动确认的风险。
本轮**从结构上消除**，而不是留着赌运气。

### 根因

SwiftUI **没有**能压过祖先 `ScrollView` 的公开 API：`highPriorityGesture` 只影响当前视图
与其子视图，对祖先滚动视图无效。所以只要触控板在滚动容器内，手势归属就是不确定的。

### 改法

- 新增 `Sources/App/RemoteControlDock.swift`：`RemoteControlPad` 的宿主 + 折叠外壳，
  读数栏（`滚动 x% · 缩放 x.xx× · lastEvent`）同时是展开/收起按钮，默认收起。
- `PhoneRootView`：Form 里删掉 `remoteSection`，改为
  `.safeAreaInset(edge: .bottom, spacing: 0) { RemoteControlDock() }`
  —— 挂在滚动区域**之外**，手势归属无歧义；顺带不用先滚动就能摸到遥控板。
- `RemoteControlPad`：删掉自己的 `readout` 行（读数栏已在 dock 头部），
  文档补上「不要放进 Form / ScrollView」的警告。
- `MockExternalDisplay.letterboxedRect`：新增 `reservedBottom = 96`，替身窗口在
  扣掉底部 96pt 后的区域内居中。替身窗口在 `.normal + 1` 层永远盖住主窗口，
  不主动避让的话展开遥控台时会在屏幕中段遮住遥控台标题栏（第一版展开态截图即如此）。

### 验证（本轮新增）

`xcrun simctl` 无触摸注入，仍用**临时插桩**验证渲染侧，全部验证后已还原：

- 折叠态 `dock-01-collapsed.png`：底部读数栏正常，Form 内容被自动 inset，与替身窗口不重叠。
- 展开态 `dock-02-expanded.png`：**暴露重叠 bug** —— 替身窗口压住遥控台标题栏。
- 修 `reservedBottom` 后 `dock-03-expanded-fixed.png`：触控板 / 滑杆 / 三个按钮全部完整可见，
  导航标题也不再被遮。实测替身窗口落在 device y ≈ 287..491，遥控台顶边 ≈ 552。
- 还原插桩后 `dock-04-final.png`：折叠态最终产物。

`git status --short` 确认只剩预期改动（新增 3 个文件，修改 5 个）。

只声明 external role 的后果：**纯黑屏**（其实是 `UILaunchScreen` 没被替换），
进程存活、无崩溃报告、`log show` 里一个 error 都没有 —— 极难排查。

排查手法（有效）：把根视图临时换成 `Color.red`。依然黑屏 → 与视图层无关，是 scene 没连上。
这一步把范围从「视图/桥接代码」直接锁到「scene 配置」。

规则三条：
1. `UISceneConfigurations` 存在 → 必须有 application role 条目；
2. 该条目**不能**带 `UISceneDelegateClassName`（会与 SwiftUI 自己的 scene delegate 冲突）；
3. 若把整个 `UISceneConfigurations` 删掉，SwiftUI 反而正常，代价是 iOS 17~26 的
   plist 自动连接外接屏那条路也没了。

### 结论

「纯 SwiftUI」到手机端为止。SwiftUI 的 `App`/`Scene`/`WindowGroup` 只能创建
`windowApplication` role 的 scene，**没有任何 API 能接管
`windowExternalDisplayNonInteractive`**，所以 `ExternalDisplaySceneDelegate` 与
plist 里的 external role 声明必须保留。

均实跑截图确认（`pure-05-bothroles.png` / `pure-06-nomock.png`）。
